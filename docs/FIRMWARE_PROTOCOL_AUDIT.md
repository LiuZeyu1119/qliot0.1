# 固件协议核对记录

## 核对范围

本轮以以下三份原始归档为主要证据，原 zip 未修改，只读解包位于 `build/win-debug/firmware-audit`：

- `L051DTU倾角传感器GGA_发布1(20260524).zip`
- `L051蓝牙倾角传感器GGA_发布1(20260709_引脚PB10-PB14).zip`
- `LoRaTORS485网关_发布1(20260709).zip`

## 已确认并落地的协议规则

| 协议点 | 固件证据结论 | Qt 实现/验证 |
| --- | --- | --- |
| Modbus 03/04 地址 | 请求地址直接用于 `HoldReg[i+reg]` / `InputReg[i+reg]`，因此该固件把读地址当作字节偏移，不是常规的 16 位寄存器索引。 | `DeviceCommunicationController::readModbusRegisters` 继续使用字节偏移；帧测试已覆盖。 |
| Modbus 10 地址 | 写多寄存器使用 `HoldReg[reg_addr*2+i]`。 | Qt 保持标准 10H 寄存器地址，固件侧乘 2 转为字节下标。 |
| CRC | 固件内部 CRC 返回值虽交换过高低字节，发布到线上仍是 Modbus RTU 标准低字节在前。 | 例帧 `01 04 00 00 00 04 F1 C9` 与 Qt CRC 结果一致。 |
| 浮点数 | `FloatToBytes` 按最低有效字节到最高有效字节写入缓冲区。 | Qt 按 little-endian IEEE-754 解析四字节浮点数。 |
| MCU 波特率 | 固件 `ModBytesToU32` 实际顺序为 `b0 | b1<<16 | b2<<8 | b3<<24`；9600 必须编码为 `80 00 25 00`。 | 新增 `encodeMcuBaud` / `decodeMcuBaud`，主界面读写和虚拟 Modbus 共用；有精确字节断言。 |
| LoRa 工作模式 | 上位机值 0/1/2 分别映射 A39C 模块值 2/4/1，对应定点、主从、透传。 | 新增双向映射函数，界面补全“透传模式 / Transparent Mode”，读写测试已覆盖。 |
| 传感器 AT | 归档包含 `AT,get,senID`、`AT,get,allpar`和 `AT,set,senpar`。 | `AtCommand` 已增加对应命令并有字符串精确测试。 |
| 蓝牙 AT | 蓝牙二级命令形式为 `AT,get,ble,<key>`、`AT,set,ble,<key>,<value>`、`AT,rst,ble,<key>`。 | 新增三个构建函数，对 key/value 去首尾空白并做精确命令测试。 |
| AT 状态 | 归档返回 `secparaERR_UNSUPPORT`、`secparaERR_CMD`、`ERR_CMD`、`ERR_PARAM`、`ERR_MODULE`、`SETTYP_NULL`、`ATSET_UNDEFINE` 等。 | 状态解析表已补全中英文说明和成功/失败标记。 |
| 频振索力扩展参数 | LabVIEW 保存流程会按“支座系数、单位质量、索长、截面积、弹性模量、截面惯性矩、水平夹角”拼接 `AT,set,exppar,<7 个参数>`，返回码包括 `set,exppar_OK/NUMERROR/TYPEERROR/FLASHERR`。 | Qt 保存后可发送完整 set 命令，再发 `AT,get,FVCFexppar` 回读 7 个值并逐项校验；com0com 字节级闭环已通过。 |
| 频振索力采样配置 | 目标产品的紧凑回包为 `get,senpar,<采样率索引>,<采样点数索引>,over`；例如 `8,2` 对应 800 Hz、1024 点。其他传感器固件存在较长的 `senpar` 格式。 | Qt 按字段数兼容紧凑两字段与原有多字段回包，读取、写入后回读和测量使用同一解析规则；com0com 使用真实 `8,2` 回包验证。 |
| 频振索力运行模式 | `get,mcupar` 第三项是运行模式：0=指令、1=自动、2=低功耗；第二项是 Gap。指令模式执行 B1→03 状态查询→04 读取数据；自动/低功耗模式由传感器自行触发测量，主机不发 B1。手册允许这两种模式直接 04，用户现场流程也要求持续轮询测量寄存器。 | Qt 指令模式保持单次 B1→03→04；自动模式改为长寿命会话，根据采样频率和点数计算完整采样时长，按该节拍持续执行 04。低功耗模式使用采样时长与 Gap 的较大值安排 04，避免频繁串口通讯妨碍休眠；等待中仍可立即停止。com0com 已覆盖自动模式连续两次 04、Mode=2 单次周期、表格连续入数和正常停止。 |
| 精确测量状态 | B1 启动后，状态字节 `0xFF` 表示设备仍在处理，`0xA1` 表示成功，非 `0xFF/0xA1` 失败码需立即报错。 | Qt 从约 0.64 秒固定 8 次轮询改为 20 秒总等待、100 ms 轮询；虚拟传感器连续 10 次返回 `0xFF` 后返回 `0xA1` 的闭环测试已通过。 |
| B7/B8/B9 | 不同固件对同一命令码的业务名称不同。 | 枚举保留显式别名：B7=搜索/电池，B8=启动连续采样/附加数据，B9=停止连续采样/DTU 参数保存，避免隐藏差异。 |

## 仍需实机确认

- `AT,get,stringdata` 是原 GUCDS/LabVIEW 的兼容命令，在本轮当前 AT 源码中未找到完整实现；为兼容其他已有固件未删除。
- `config,set,...` 来自原 LabVIEW 和 DTU 网络链路，不是蓝牙/网关 AT 解析器的通用命令，需用实际 DTU 核对字段和保存时序。
- B7/B8/B9 必须根据所选产品/固件类型解释，不应只根据命令字节推断唯一业务语义。
- 频振索力技术手册示例的状态请求地址为 `0x0001`，但当前目标设备实测使用 `0x0002` 可稳定返回 `FF/A1`；本地固件也将状态写入 `HoldReg[2]` 且 03H 按字节下标读取。本版以当前实机成功报文为准保留 `0x0002`，不同固件批次若采用标准寄存器寻址需另做实机兼容验证。
- 已检查的 L051 倾角传感器源码中，`GET_FVCFEXPPAR` 输出被注释，`SET_EXPPAR` 分支为空；它不能作为频振索力传感器参数持久化的正向证据，最终仍需对目标索力传感器固件和实机回读进行确认。
- 本轮已完成帧、虚拟设备、com0com 和截图验证，但不能代替目标批次传感器的串口时序、断线恢复和异常码实测。
